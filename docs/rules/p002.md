# P002 unknown-task

CI calls a task that the task runner doesn't define.

**Severity:** error.

## Example

```yaml
# Taskfile.yml defines `lint:ci` and `test`, but no `lint`.
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - name: Lint
        run: task lint
```

```text
.github/workflows/ci.yml
  7:19   P002 unknown-task  'task lint' is not defined in Taskfile.yml (closest: lint:ci)
```

The closest existing name is suggested: a task that starts with the unknown name first,
otherwise the nearest spelling.

## Why it matters

The step fails only when its workflow next runs, which for a release or nightly workflow
can be long after the task was renamed or removed. ci-parity catches it in the pull
request that made the change.

## How to fix it

Call the task by its current name, or add the task to the runner file. Tasks from
`includes` (Taskfile), `include`s (make), `import`s and modules (just) and
`task_config.includes` (mise) all count as defined.
